# Implementation Plan: Setup Wizard Layout Cleanup

**Branch**: `031-setup-wizard-cleanup` | **Spec**: [setup-wizard-cleanup.spec.md](./setup-wizard-cleanup.spec.md) | **Size**: `normal`

## Summary

The wizard's first tab currently renders four components stacked together: `GeneralAppearanceTab` (name, currency, financial year, inception), `MembershipFeesTab` (fees, renewal month, audit retention), `ThemeSelectionTab` and `SalesTaxTab`. This change regroups those fields into two tabs without changing any captured value, default or validation rule.

The Organisation tab keeps the name, theme, renewal month and audit retention. A new `AccountingTab` component takes currency, financial year, inception date, the two fee fields, and hosts the existing `SalesTaxTab` below them, so each fee sits above its tax treatment. `SetupWizard` grows from five tabs to six, and the Review tab gains two headed groups and the accounting values it does not show today. Language and sample data stay on `/language-select` (spec 029) and are not touched. The sample-data path already skips the wizard, so that story is covered by an audit of the placeholder request and seeder, plus a regression test.

No data model, service, entity or migration changes. All other tabs and the form model are unchanged.

**Structure Decision**: Re-compose existing components rather than rewrite them. Only fields move; element ids (`orgName`, `setup-currency`, `annualFee`, `taxApplicable`, and the rest) stay exactly as they are, so no consumer or test selector changes except where a test renders the wrong component.

## Notes for implementation

- The tab strip index is hard-coded in `SetupWizard` (`_tabShown` list, `SetActiveTab(n)` per tab). Inserting Accounting at index 1 shifts every later index, so update all `SetActiveTab` calls and the `_tabShown` initial list together.
- `MembershipFeesTab` hard-codes a `$` prefix on the fee inputs. Moving them unchanged keeps this work behaviour-neutral. It is a known gap, left out of scope.
- `SalesTaxTab` wraps its content in `col-md-6`/`col-12` columns that assume a surrounding `row g-3`, as `SetupWizard.razor` provides today. `AccountingTab` must supply the same wrapping row.
- The existing Organisation tab key `Setup_Tab_OrganisationSettings` keeps its wording; only `Setup_Tab_Accounting` is new for the tab strip. This avoids re-translating a label that is already correct.
- Sample data (US4, FR-013/14): `FirstRunLanguageScreen` builds a placeholder `SetupRequest` and `DebugDataSeeder.ApplyGeneratedOrganisationSettingsAsync` overrides name, fees, renewal months and seat target. Currency, tax, financial year, inception date and audit retention are left at valid defaults. The audit task confirms nothing a wizard tab asks for is left invalid, and adds a test that the placeholder request is accepted.
